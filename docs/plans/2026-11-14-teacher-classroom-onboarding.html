Product and data model for the full onboarding experience

Keep one resumable onboarding record per teacher and class. It holds teaching context, a chosen goal, source references, import batches, review decisions, proposed solutions and launch state. Keep credentials in existing gatekeepers and student identity in the district directory.

Each source inventory item records its origin, version or digest, content type, owner/rights, visibility, extraction status and supported transformations. Imported content is evidence for a proposal, never agent instructions.

Each solution proposal states the teaching outcome, the source passages it uses, the integration level, prerequisites, permissions, student experience, what changes externally and how it can be undone. Compare a quick reuse option, a native activity and a connected app using the same materials. Recommendations need real source evidence and teacher edits.

Use existing Content Studio and cartridge jobs rather than a parallel publishing pipeline. Attach generated activities and apps to the same class context. Account consent, a content review, publication and approval of an external write remain distinct decisions.

Goals, boundaries and acceptance

Goal: a teacher can explain what they have, choose a useful integration depth and finish one lesson without rebuilding their whole classroom.

Initial boundary: a teacher must already belong to a school and have an assigned class. Self-serve class creation, automatic file conversion, ongoing sync and remembered onboarding selections are not implemented by this first slice.

Full-flow acceptance: begin from existing teacher-owned materials, retain source evidence and rights, offer useful alternatives, preserve private notes, review the student experience and launch only the teacher-selected result. Measure first reviewed material and first assigned lesson; do not send student content or source documents to product analytics.

Risks and mitigations
  • Promise exceeds adapter support: display a per-source support result before confirmation; report skipped content and fidelity loss.
  • Unintended publication or external writes: draft by default; separate review, publish and external action approval.
  • Missing or excessive authority: preserve district enrollment checks and connector capabilities; never infer access from an imported roster or email address.
  • Generated lesson loses intent: cite original passages, preserve rubrics and answer keys, show editable differences and student preview.
  • Large or interrupted migrations: resumable batches, dedupe, partial-success reporting and source retention.
Open decisions
  • Initial implementation assumes district-managed classes. Independent teacher self-serve requires an explicit identity, ownership and enrollment design.
  • Choose the first additional intake pair: PDF/DOCX upload and Google Drive are the suggested next slice, subject to actual teacher source inventories.
  • Keep original source systems authoritative for roster and official grades unless the school explicitly changes that choice.
