# EducateOS

EducateOS turns this Workshop into a district-owned K-12 learning environment. A district installs it
into its own Cloudflare account. Students, teachers and administrators then work inside it without
operating developer infrastructure themselves.

EducateOS is open source (Apache-2.0) and is not a hosted service. Every organization that installs it
runs all of it in its own account ([ADR-0011](adr/0011-open-source-charter-and-module-ownership.md)).

This directory holds the decisions and contracts EducateOS is built on. The execution roadmap (PR IDs
such as F01 and A02) lives in the EducateOS Kanbanger project, which uses the `SCHO-` issue prefix.

## Running the districts locally

```sh
pnpm educateos:harness            # the six districts on :4801 to :4806, until Ctrl-C
pnpm educateos:harness -- --check # boot, check every /health over HTTP, exit
```

Each district file lists its deliberate edge cases: a shared family email, a student dropped
mid-term, guardians (one relationship still pending), a teacher in two schools, Morgan Lee's
email and subject in two districts, two different students sharing one IdP subject, and
Lakeshore's large-removal export (`lakeshoreLargeRemoval`). `vendorSeeds(demo)` gives the records
each district's providers hold. Harbor and Cedar Valley also exist in the Google demo tenant
`gedu.demo.educateos.io`, seeded by `scripts/demo/seed-google-demo.ts` (see its header).

Each district serves `GET /health`, `GET /me` and `POST /ai/complete`, and the full district
application under `/api/` (see `@educateos/district-app` below), seeded with demo content: an approved
resource and an installed activity in every active class, a student's essay in a personal and a
course workspace, one submission, an applied configuration revision and one AI request. The harness
prints a ready-made `curl` command with a token for one student, one teacher and one district
administrator per district. A token from one district's IdP is rejected by every other. Sign-in takes
the production path: each token's verified payload goes through `identityFromAccessPayload` and the
directory's `createDirectoryPrincipalResolver`, and the CLI shows Morgan Lee (one IdP subject in
Northfield and Riverbend) landing on a different principal in each. `EDUCATEOS_HARNESS_PORT` moves the first port.

## Rules every EducateOS change follows

- No student or teacher content leaves the district's account. educateos.io (formerly `educateos.io`)
  is never in the data path ([ADR-0013](adr/0013-educateos-open-core-control-plane.md)).
- EducateOS runs entirely in the organization's account. educateos.io may host documentation,
  releases, a guided install, an installation dashboard, billing for the services it performs,
  and a marketplace. It never mediates runtime access, issues runtime tokens, holds standing
  credentials for an installation or gates features.
- No paid-gated core: no entitlement checks, subscription callbacks, student-data fleet reporting or
  remote administrative access in the default runtime. A paid marketplace item is a signed
  artifact verified offline. Instance registration is opt-in, content-free and off by default.
- Every installation works on the organization's own domain. `<slug>.educateos.io` is a default
  hostname, not a dependency.
- Releases are verified offline against keys the organization pins.
- Claims about standards support match [maturity.md](maturity.md). No 1EdTech certification is
  claimed.
- Identity is `(district, issuer, subject)`. Email is display metadata.
- Every HTTP route, MCP tool and agent action authorizes through the same vocabulary and denies by default.
- Narrower scopes may tighten district policy, never loosen it.
- Closing a term, dropping an enrollment or losing a roster row never deletes work.
- Tests use `@educateos/fixtures` and reserved `.example` domains. Never use real people.
