Shared Hall Monitor + AI cost governance Reconciled plan · building

2026-10-20 · repos: gmackie/hall-monitor (new, GitHub, public) · gmackie/educate-os (ForgeGraph) · gmackie/playtrek (ForgeGraph) · source: EducateOS_Hall_Monitor_Cost_and_Milestone_Master_Plan.md + doc set

Decision: build Hall Monitor as a product-neutral service and SDK in gmackie/hall-monitor. Do not build a new cost ledger. Extend EducateOS's existing @educateos/ai-governance (SCHO-25) to integer USD-nano amounts, price books and per-attempt receipts. Then hook both into the Workshop kernel at the one function every model request already goes through.

The source plan was written without SCHO-25 (merged reserve/settle ledger, pools, reconciliation) or SCHO-31 (commerce). It also missed that steerRunningTurn, agent callbacks and spawnAgent all skip the shared message preparation step.

Architecture

Solid edges carry evaluation requests (a service binding within the same account, signed short-lived JWT over HTTPS across accounts). Dashed edges carry content-free cost receipts into the ledger of whoever owns the bill. Nothing goes through educateos.io.

Key decisions

Repo & distribution

gmackie/hall-monitor is a pnpm workspace: contracts, costing, policy, evaluators, clef, core, client, apps/worker. Packages export TypeScript source, and consumers pin a commit with a pnpm git dependency. Publishing to npm as @gmacko/* (like @gmacko/lti) waits for your approval (OPS-01).

Money

Amounts are integer UsdNano (10⁻⁹ USD), as a decimal string on the wire and bigint internally. Price rates are rational. Rounding up to cents happens only for display and invoices. ai-governance migrates fully; assessment-ai and fleet switch at their boundaries and get follow-up issues.

Kernel seam

A single optional AI_CALL_GUARD hook: the kernel calls beforeModelCall / afterModelCall with content-free metadata plus only the new messages. Upstream behaviour is unchanged when it's unbound. EducateOS supplies the implementation (ledger governor plus Hall Monitor client), so its package code stays out of the kernel.

Safety funding

A new safety pool purpose, which only the district admin can configure. Hall Monitor spend is drawn from it, never from a student or teacher wallet. If the safety pool is exhausted, generative calls are blocked and a safe non-AI path is offered; moderation is never skipped.

Failure policy

Behaviour depends on the action and the audience. For student-facing modes, Hall Monitor being unavailable means AI is unavailable (fail closed, with a support path). Educator-only modes may use the approved deterministic fallback. The resolver never lets a model make up an action string.

Privacy

Prompts are never written to receipts, the ledger, metrics labels or logs. Gateway calls send cf-aig-collect-log-payload: false. Text is processed in memory. A human-review store (UI-04) stays gated until the privacy review is done.

Not something an agent can complete

  • Human COPPA/FERPA/DPA legal and privacy review; parental consent basis; approval of the safeguarding route. This blocks any student rollout and UI-04.
  • Human Calibrating Clef thresholds on human-labelled reference data. The code ships with honest placeholders and reports precision and recall for each class.
  • Credentials Live import of Cloudflare and provider billing (COST-06 against real accounts) needs least-privilege API tokens. Fixtures are used until then.
  • Approval Publishing @gmacko/hall-monitor-* to public npm, and deploying the Worker to production accounts.
  • Pilot M7 pilot: shadow → educator-only → opt-in staff → grades 6–12, each step signed off by people.

Risks

High Kernel diff size. The guard touches the hottest code in the repo. Keep it to one hook interface and six call sites, in its own PR; all policy logic lives in EducateOS packages.

High Transcript re-moderation cost and latency. stream sees the whole transcript on every step. Track the moderated message index per chat and only check messages added since; key a cache on digest + policy + evaluator version.

Med Cents → nano migration of stored entries. The in-memory store is the only one shipped, so no persisted data needs migrating. Add a versioned entry schema with a parse-time upgrade from *Cents fields anyway.

Med Public repo leakage. No PlayTrek source and only synthetic fixtures. A CI grep blocks @playtrek/ imports.

Med Streaming output moderation. Student modes buffer output until it is released; educator modes stream. Each profile declares which it uses.

Verification

Hall Monitor: pnpm test (vitest + workerd) and GitHub Actions on every PR. EducateOS: pnpm lint plus the package suites (vp run -F), with ForgeGraph CI green on the head revision before auto-approval. PlayTrek: turbo test/typecheck/oxlint for the packages touched. Cross-product acceptance: a synthetic co-op (12 teachers, 60 students) runs end to end with duplicate events, timeouts, an exhausted student wallet and the root offline.

Open questions

None blocking. Defaults chosen: a pnpm git dependency until npm publishing is approved; a Kanbanger Hall Monitor project in team GMA; GitHub PRs for hall-monitor and ForgeGraph PRs for educate-os and playtrek.
