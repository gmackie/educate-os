Connectors

Connect the tools your school already uses, one resource at a time.

Cloudflare OS calls its connectors gatekeepers. Each one runs as its own Worker and stands between an agent or gadget and an outside service. EducateOS uses Cloudflare OS's gatekeepers for every service outside the district's own data, and adds one for the district's school tools.

Available in Cloudflare OS In development Planned Each status matches the project's maturity record. Nothing here claims more than the code shows.
How a gatekeeper works

Access is introduced, reads are recorded, and writes wait for a person.

Nothing by default

An agent or gadget starts with access to nothing. A person introduces each resource, such as one Drive folder or one GitHub repository, by pasting a link or picking it from a list. An agent can ask for an introduction, and the person can say no.

Reads are recorded

Reading data returns straight away and is recorded as an observation, so there is a record of what an agent looked at. Each gadget runs in a sandbox and reaches the internet only through the gatekeepers it was given.

Writes wait for approval

Anything with side effects is queued. The gatekeeper simulates the result so the agent keeps working, and a person approves or rejects the queued actions later, all at once or one by one.

Available in Cloudflare OSThe gatekeeper model, gadget sandboxes and the approval queue are part of Cloudflare OS today.

For teaching and learning

The connectors a classroom will reach for first.

G

Google Workspace

Drive, Docs, Sheets, Slides, Gmail, Calendar and Chat. A person grants one resource at a time, such as a single folder, document or calendar. Signing in with Google reads only the verified email.

Available in Cloudflare OS
GC

Google Classroom

Part of the Google connector: a course's details, teachers and students, and coursework that the connector creates and grades. Google lets an app change only coursework it created. The school's Workspace admin must allow Classroom data access.

In development
CL

Context Library

Collections of documents that agents read as background. District admins can publish public collections, such as AI guidelines or a curriculum guide, which every user gets. Anyone can keep private collections and share them.

Available in Cloudflare OS
WS

Web Search

Searches the public web through Cloudflare's Web Search API. The admin sets it to off, optional or on for everyone. Each query is recorded before it is sent, and searches spend the account's AI Gateway credits.

Available in Cloudflare OS
ST

Scheduled Tasks

Recurring or one-time jobs, such as a Monday summary of what's due. A new schedule stays switched off until a person enables it in Connections, and a read-only page lists every schedule in the account.

Available in Cloudflare OS
@

Email

Gives a gadget its own address for incoming mail, for example a field-trip form inbox. Mail arrives through a Cloudflare Email Worker and reaches the gadget already parsed.

Available in Cloudflare OS
Your district's data and tools
E

School tools for agents

Gives a Workshop agent the district's school tools. A person connects their school account once. Every call then acts as that verified person, never as someone named in the tool's input, and goes through the same default-deny policy as the district app. School writes need confirmation.

In development
M

MCP servers and the MCP Server Portal

Connect any Model Context Protocol server, or one portal the administrator chooses that fronts the servers the district has approved. Read-only tools return straight away and everything else queues for approval. Read about MCP →

Available in Cloudflare OS
For staff, CS classes and makers

Collaboration tools for staff, and real developer tools for students.

GH

GitHub

Repositories, issues and pull requests. A class agent can draft a change, and a push or merge waits in the queue for the person who owns the repository.

Available in Cloudflare OS
GL

GitLab

The same model for gitlab.com or a school's self-hosted GitLab: projects, issues and merge requests, with pushes queued as actions.

Available in Cloudflare OS
SB

Supabase

A hosted Postgres project for a databases class: schema introspection and read-only SQL, with any SQL that changes data held for approval.

Available in Cloudflare OS
CF

Cloudflare

Cloudflare sign-in, AI Gateway billing, and read-only Workers Observability (logs, metrics and traces) for one Worker or a whole account. Useful when students deploy their own Workers.

Available in Cloudflare OS
N

Notion

Pages and databases in a staff or club workspace, connected through Notion's own sign-in.

Available in Cloudflare OS
S

Slack

Read-only access to channels, direct messages, threads and search, limited to what the connecting person can see. It never sends or changes anything in Slack.

Available in Cloudflare OS
C

Confluence

Spaces, pages, blog posts, comments and attachments on Atlassian Cloud, with page bodies converted to and from Markdown. Server and Data Center editions aren't supported.

Available in Cloudflare OS
L

Linear

Issues, labels, states and cycles for one team, or a single issue and its comments. Handy for a robotics team or a student software project.

Available in Cloudflare OS
And more. Cloudflare OS also ships gatekeepers for Home Assistant, Spotify, X and ZoomInfo. They are built for home and business use, and most schools will leave them unconfigured. Every gatekeeper needs its own credentials set up before anyone can connect it.
Education integrations

Rosters and LMS links, built to the standards and labeled honestly.

These connect EducateOS to a district's student information system and learning management system. Each feature carries its own status. Some are being validated against live sandboxes, and none is yet marked Supported.

EducateOS claims no 1EdTech certification. Where it says "LTI 1.3" or "OneRoster 1.2", it means code written to that specification and covered by unit tests, not certified conformance.
