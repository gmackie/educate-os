For district IT · Security review

Security questionnaire, answered

Pre-filled answers to the questions district IT and procurement security reviews ask most often. Each answer names the document or code it rests on, and says plainly what is not done yet.

Version of November 13, 2026. The canonical copy is docs/educateos/security-questionnaire.md in the open-source repository.

Print or save as PDF

The district runs it

EducateOS is open-source software (Apache-2.0) that the district installs in its own Cloudflare account. Its data, logs, keys and backups live there. Gmacko Ventures LLC, which develops EducateOS, does not receive student data. Where a question asks what the vendor does with student data, the answer is not applicable, and the district's control of its own account is the answer instead.

What we don't have yet

No real students use EducateOS yet. There is no SOC 2 report, no ISO 27001 certificate, no independent audit and no penetration test. EducateOS is built to support the district's FERPA and COPPA obligations; it is not certified, and the district makes its own legal review. The DPA template is a draft pending counsel review.

How to read the status. In place true today, in the code or the Cloudflare platform. Built, not proven in a district code exists at the maturity level named, but has not run in a real district. Not done not built or not done, or not yet known. Not applicable or District decides the district's own account, setting or process. Levels follow the capability maturity table. Cloudflare facts cite Cloudflare's public documentation; Cloudflare publishes its own compliance reports at cloudflare.com/trust-hub, and we make no claim about them.

2. Data location and residency

QuestionAnswer and sourceStatus
Where is student data stored?In the district's own Cloudflare account: Workers, Durable Objects (SQLite) and, where enabled, KV, R2 and D1. The district application keeps its records in one SQLite Durable Object per district. Nothing is stored in an account Gmacko Ventures LLC controls.Source: ADR-0001 rule 1; packages/educateos-district-worker/src/worker.ts, district-object.ts; maturity.md, District application rowIn place (design)Built, not proven in a district
Does any student data reach educateos.io or Gmacko Ventures LLC?No, in the normal course. educateos.io hosts the website, releases, an optional guided install and an optional managed hostname. No classroom path calls it. Instance registration is opt-in, content-free and off by default.Source: ADR-0011 decisions 3, 4, 7; ADR-0013; README.md, "Rules every EducateOS change follows"In place (design)
What about the optional <slug>.educateos.io hostname?It is routing only: the hostname, certificate, Worker route and Access application live on a zone in the district's account, and educateos.io publishes DNS records. Gmacko Ventures LLC configures no logging, storage or inspection of requests. A district can use its own domain instead, and must for now if its account does not hold educateos.io.Source: ADR-0013 decision 4 and addendum A1; installer-permissions.md, "Managed-only installs" (SCHO-243)Built, not proven in a district
Is data kept in the United States?Not guaranteed today. EducateOS does not set a Durable Object jurisdiction, so Cloudflare places each object near the first request that creates it; for a US district that is normally a US data center, but it is not a contractual guarantee. Cloudflare offers us, eu and fedramp jurisdictions; EducateOS does not use them yet.Source: packages/educateos-district-worker/src/worker.ts (getByName, no jurisdiction); developers.cloudflare.com/durable-objects/reference/data-location/Not done
Can the district export or take its data elsewhere?Yes. A district administrator exports the whole district (directory, course work and submissions with their files, grades, feedback, class content, weekly notes, Content Studio materials, activities, rubrics, the course library and marketplace packs, guardian relationships, configuration) as one ZIP of JSON and content files, from the admin console or an admin-only, audited endpoint. It is streamed, so there is no size limit (SCHO-367); it has not yet been timed against a large district. Teachers can also export a course as Common Cartridge and a gradebook as CSV. Students' personal workspaces are not in the district export: each student downloads their own work (personal workspaces, finished classes' work, their submissions and the feedback shared with them) as a .educateos archive from the Student app, every item decided and audited by the policy engine, while they can still sign in (SCHO-371). The district also holds the account, so its data never leaves its control. Leaving is described in the offboarding runbook.Source: packages/educateos-district-app/src/routes.ts (admin.exportDistrict, student.exportArchive, teacher.exportCartridge, teacher.exportGradebookCsv); educateos-archive-format.md; runbooks/district-offboarding.mdHarness-tested, not proven in a district

3. Encryption

QuestionAnswer and sourceStatus
Is data encrypted at rest?Yes, by Cloudflare. Durable Object data and metadata are encrypted with AES-256 (LUKS); KV and R2 with AES-256-GCM. Keys are managed by Cloudflare. EducateOS adds no application-level encryption of records.Source: developers.cloudflare.com/durable-objects/reference/data-security/, developers.cloudflare.com/kv/reference/data-security/, developers.cloudflare.com/r2/reference/data-security/In place (platform)
Is data encrypted in transit?Yes. Public traffic is HTTPS, terminated by Cloudflare in the district's account. Traffic between Workers, Durable Objects and Cloudflare's network uses TLS. Worker-to-Worker calls use service bindings inside the account.Source: Same Cloudflare pages; ADR-0014In place (platform)
Can the district hold its own encryption keys?No. Cloudflare manages storage encryption keys. The district holds its integration credentials and signing keys as Worker secrets.Source: Cloudflare pages aboveNot done
How are secrets stored?As Cloudflare Worker secrets in the district's account. Cloudflare does not show a secret's value in the dashboard or Wrangler after it is set. The release signing key is a CI secret on the publisher's side and is never written to disk.Source: developers.cloudflare.com/workers/configuration/secrets/; release-signing.md; packages/educateos-ai-guard/README.mdIn place

4. Access control and administrative access

QuestionAnswer and sourceStatus
How do users sign in?Through Cloudflare Access in the district's account, using the identity provider the district already uses (SAML or OIDC; Google, Microsoft Entra ID, Clever and others). The district Worker verifies the Access assertion (signature, issuer, audience, expiry) and resolves it to a person in the district's own directory. Setting Access closes the Workshop's password sign-in.Source: packages/educateos-district-worker/src/access.ts; ADR-0003; runbooks/production-instance.mdIn place (Access sign-in)Built, not proven in a district (directory)
How is authorization decided?One default-deny rule table decides every school read and write, using the person's identity, role and enrollments. Requests across districts are refused before any rule runs. Identity comes from sign-in, never from a tool argument or model output. Level: Harness-tested.Source: packages/educateos-policy; ADR-0010; threat-model.md T1-T5; maturity.md, Policy engine rowBuilt, not proven in a district
Can students see each other's work, or teachers see students' private AI chats?Policy denies both. Artifact isolation is tested over the API. Personal-chat privacy is tested at the policy engine but not yet over the API, because the chat routes are missing (SCHO-107).Source: pilot-gate.md, Roadmap §14 rows 2-3Built, not proven in a district
Do agent writes need a human?Yes. Grades and other records an agent drafts wait for a teacher's approval. Level: Harness-tested; school tools are Deployed for the demo district.Source: packages/gatekeeper-educateos; packages/educateos-policy/src/approvals.ts; maturity.md, School tools rowBuilt, not proven in a district
What happens when a person leaves or is deactivated?Access is revoked on the next request. Capabilities already issued in the Workshop are revoked by restarting the objects that hold them, within a bounded delay.Source: security/live-capability-revocation.md; pilot-gate.md (revocation mid-session)Built, not proven in a district
Who are the administrators?District administrators, named by the district. The last administrator cannot be removed. Cloudflare account roles are the district's.Source: packages/educateos-district-app/src/routes.ts (admin.grantDistrictAdmin, admin.revokeDistrictAdmin); admin.mdDistrict decides
Does Gmacko Ventures LLC have standing or remote administrative access?No. The default runtime has no remote administrative access for anyone outside the district. The guided install uses a credential for the length of the install only, and the district then deletes or revokes it.Source: ADR-0011 decision 4; installer-permissions.md; DPA template §9Not applicable
What if the district wants vendor support with its data?Only at the district's written request, with credentials the district grants and revokes, limited to the task, and recorded (DPA §6, draft). An optional hosted operations console (admin.educateos.io) is designed so a district can enroll it with scoped keys it can remove; its directory scope would show the district's people list. It is not deployed, and no district has enrolled it. An open-source edition runs in the district's own account instead.Source: DPA template §6; admin.mdNot done
What can the installer credential reach?Cloudflare's permission groups are coarser than the installer needs, so the limit is in the code: the installer has no operation that reads KV values, R2 objects or Worker logs, and runs only migration SQL against D1.Source: installer-permissions.md, "What the credential can reach"Built, not proven in a district

5. SSO and MFA

QuestionAnswer and sourceStatus
Do you support SSO?Yes, through Cloudflare Access with the district's identity provider. Clever SSO through Access is Harness-tested; ClassLink sign-in is Implemented, tested against fakes only. The admin console's Sign-in screen shows, read-only, the configured provider, the issuers the district trusts and how many people each signs in, and no secret (SCHO-376).Source: maturity.md, Clever SSO and ClassLink rows; packages/educateos-identity/src/clever-sso.tsIn place (Access)Built, not proven in a district (Clever, ClassLink)
Is MFA enforced?The district enforces MFA in its identity provider or in its Access policy (Access can require an MFA authentication method, or prompt for MFA itself). EducateOS has no passwords of its own to protect.Source: developers.cloudflare.com/cloudflare-one/access-controls/policies/mfa-requirements/District decides
Session length and timeout?Set by the district in its Access application.Source: Cloudflare Access application settingsDistrict decides
Is email used as an identity key?No. Identity is (district, issuer, subject). Email is display metadata, so a shared family email cannot take over an account.Source: ADR-0003; threat-model.md T4Built, not proven in a district

6. Sub-processors

QuestionAnswer and sourceStatus
Which sub-processors handle student data for Gmacko Ventures LLC?None. Gmacko Ventures LLC receives no student data. For its own website and services it uses Cloudflare (hosting, DNS, operator sign-in, email routing), an email provider, and Stripe once billing exists; none receives student data from Gmacko Ventures LLC.Source: DPA template §8; sites/educateos-io/public/privacy/index.htmlNot applicable
Which third parties does the installation itself use?The district's own: Cloudflare (always), its identity provider, and the integrations it turns on (for example Google Classroom, Clever, ClassLink, an LMS). AI models run where the district configures them: Workers AI in its Cloudflare account, or other providers through its AI Gateway under the district's agreement with them. These are the district's sub-processors, under the district's contracts.Source: runbooks/production-instance.md; docs/ai-gateway-conventions.md; maturity.mdDistrict decides
Will you notify us before adding a sub-processor?The draft DPA promises 30 days' notice before adding one that would receive student data.Source: DPA template §8Not done (DPA draft)

7. AI and model data use

QuestionAnswer and sourceStatus
Is student data used to train AI models?Not by EducateOS or Gmacko Ventures LLC. Cloudflare states that it does not use Workers AI customer content (prompts, outputs, embeddings) to train models and does not keep inputs or outputs after a request unless a storage or logging feature is turned on. Other providers a district adds are governed by the district's agreement with them.Source: developers.cloudflare.com/workers-ai/platform/data-usage/In place (platform, Workers AI)
Are prompts logged?Not by default. The installer creates the AI Gateway with logging off, because gateway logs would hold prompts. Server code must never log prompts, secrets, headers, tokens or request bodies.Source: packages/educateos-installer/src/cloudflare-http.ts (createAiGateway, collect_logs: false); packages/observability/AGENTS.mdBuilt, not proven in a district
How is student AI use screened?Before a model sees a new message, the AI call guard sends it to Hall Monitor and applies the decision. Student profiles must also screen model replies before a student sees them, and fail closed when Hall Monitor is down. Hall Monitor runs in the district's own account; there is no hosted Hall Monitor. Level: Deployed (guard, from source) for the demo instance.Source: packages/educateos-ai-guard/README.md; ADR-0007 and its 2026-10-21 note; maturity.md, AI call guard rowBuilt, not proven in a district
Can AI spend be capped?Yes. Every call holds its maximum cost against the person's allowance on the district's own ledger, then settles at the actual cost. Safety checks come from a separate pool.Source: packages/educateos-ai-guard; threat-model.md T9Built, not proven in a district
Can AI make an official grade?No. An AI-suggested score stays a suggestion until a teacher approves it. Tested at the policy and assessment layers; the over-the-API check waits on SCHO-107.Source: threat-model.md T10; pilot-gate.mdBuilt, not proven in a district
Can the district turn AI off?Yes. Student AI can be turned off entirely; teacher-facing AI starts off.Source: sites/educateos-io/public/student-privacy/index.html (COPPA section); packages/educateos-district-worker/src/ai-disabled.tsBuilt, not proven in a district
Do you profile students or advertise?No advertising, no sale of data, no profiling for non-school purposes. Automated social-emotional profiling is prohibited in every policy profile.Source: packages/educateos-contracts/src/policy-floor.ts (automatedSelProfiling); sites/educateos-io/public/student-privacy/index.html; DPA template §7Built, not proven in a district

8. Logging and audit

QuestionAnswer and sourceStatus
Are access decisions audited?Yes. Every authorization decision is written to an audit trail with who, what action, which resource, the outcome and the deciding rule, as identifiers only, never content. If the audit record cannot be written, the request is refused. A district administrator reads them, read-only, in the admin console: Safety decisions lists every decision, filtered by outcome, rule and record kind, with Hall Monitor's decisions on discussion posts; Admin audit log lists the changes administrators were allowed to make. Only a district administrator, signed in as a person, can open either (SCHO-376).Source: packages/educateos-policy/src/audit.ts, durable-object-audit-sink.ts, engine.ts; packages/educateos-admin-ui/src/audit/Built, not proven in a district
Are agent and gadget actions logged?Gatekeepers log every action and read an agent or gadget makes. EducateOS adds a record of each AI call attributed to a person, class and feature.Source: sites/educateos-io/public/security/index.html ("An audit trail"); packages/educateos-ai-guardIn place (action log, Cloudflare OS)Built, not proven in a district (AI call records)
Are sign-ins logged?Cloudflare Access records sign-ins in the district's account.Source: Cloudflare Access logsIn place (platform)
Are operator actions audited?If the district enrolls an operations console, every verified request is recorded in the district for 400 days. Not deployed.Source: admin.md, "The district side"Not done
Where are logs kept, and for how long?In the district's Cloudflare account, under its retention settings. Gmacko Ventures LLC receives none.Source: ADR-0001; packages/observability/AGENTS.mdDistrict decides
Do logs contain sensitive data?The logging rules forbid secrets, prompts, headers, tokens and request or response bodies.Source: packages/observability/AGENTS.md; REVIEW.mdIn place (rule)

9. Retention and deletion

QuestionAnswer and sourceStatus
How long is data kept?The district decides. A closed course's workspace is kept for a district-set number of days (default 365), then becomes eligible for deletion. A legal hold blocks deletion, and each deletion leaves a tombstone. Students' personal workspaces are not removed by this process. The retention job is unit-tested but is not scheduled in the district Worker yet.Source: packages/educateos-workspaces/src/retention.ts, lifecycle.ts; packages/educateos-district-app/src/app.ts (default 365); packages/educateos-district-worker/src/config.ts (retention)Built, not proven in a district
Does ending a term or a roster removal delete work?No. Access is revoked; people are deactivated, not deleted; enrollments are kept as history. A sync that would deactivate a large share of people is held until an administrator approves it.Source: threat-model.md T6; maturity.md, OneRoster and Clever rowsBuilt, not proven in a district
How is data deleted at contract end?The district owns the account and deletes its resources. Gmacko Ventures LLC holds nothing to delete, except anything it held under Support Access, which the draft DPA requires deleted within 30 days with written confirmation.Source: DPA template §11Not applicable
Can parents request access, correction or deletion?Requests go to the district, which holds the data. Gmacko Ventures LLC forwards any it receives within 5 business days (draft DPA).Source: DPA template §12District decides

10. Backups and recovery

QuestionAnswer and sourceStatus
Is data backed up?The district's data lives in its own account, so backups are the district's. Cloudflare offers 30-day point-in-time recovery for SQLite Durable Objects; EducateOS has no restore procedure or tooling that uses it yet.Source: developers.cloudflare.com/durable-objects/api/sqlite-storage-api/; pilot-gate.md, "Restore rehearsal"Not done
Has restore been tested?Only in memory: a district's stores are snapshotted and restored into fresh stores, and the views compare equal. The rehearsal found items that a durable backup must still cover. A real restore of deployed storage has not been rehearsed.Source: pilot-gate.md, "Restore rehearsal" (SCHO-108)Not done
What are your RTO and RPO?None committed.Source: This documentNot done
What if educateos.io goes down?Classroom activity continues: no classroom path calls educateos.io. This is a required pilot-gate test.Source: ADR-0001 rule 4; ADR-0013Built, not proven in a district
Can a bad update be rolled back?Yes. The installer redeploys the previous Worker versions. Database migrations are listed as irreversible, and the district acknowledges each before approving a release.Source: installer-permissions.md; release-signing.mdBuilt, not proven in a district

11. Incident response and breach notification

QuestionAnswer and sourceStatus
Do you have an incident response plan?No written incident response plan exists yet.Source: Not yet documentedNot done
Who do we contact about a security issue?hello@educateos.io is the only published contact. There is no dedicated security address or vulnerability disclosure policy yet.Source: sites/educateos-io/public/security/index.html; not yet documentedNot done
How fast will you notify us of a breach?For student data Gmacko Ventures LLC holds or accessed (only under Support Access), the draft DPA says within 72 hours. For the installation itself, the district operates it and runs its own response; Gmacko Ventures LLC will help on request.Source: DPA template §10Not done (DPA draft)
What if your release key is compromised?Releases are signed and the district verifies them offline against keys it pinned. A stolen online release key cannot change the district's trust; only a key set signed by a threshold of offline root keys can. Until a new set lands, the district's approval of each release is the defence.Source: threat-model.md T12; release-signing.mdBuilt, not proven in a district

12. Vulnerability management and secure development

QuestionAnswer and sourceStatus
How are dependencies kept current?Dependabot opens grouped npm and GitHub Actions update PRs on the 1st and 15th of each month, with a 7-day cooldown (14 for majors). pnpm refuses package versions younger than a day.Source: .github/dependabot.yml; pnpm-workspace.yaml (minimumReleaseAge)In place
Do you scan for vulnerabilities?Yes, for dependencies. CI runs pnpm audit against every pnpm lockfile on each pull request, each push to main and nightly. A pull request that adds a high or critical advisory in a production dependency fails. Advisories already present are listed in a checked-in baseline, each with a reason, a tracking issue and an expiry; there are none critical. There is no static-analysis (SAST) scanner for EducateOS's own code.Source: .forgejo/workflows/ci.yml; security/dependency-scanning.mdIn place
How are patches applied to a district?The district applies a signed release with the installer when it chooses. There is no automatic update.Source: release-signing.md; launch-installer.mdBuilt, not proven in a district
What is your secure development process?Every change goes through a pull request; CI runs lint, type checks, builds, the EducateOS package tests, the pilot gate's security matrix and a dependency vulnerability audit before merge. Review guidelines put capability-security invariants and secret leakage first.Source: .forgejo/workflows/ci.yml; REVIEW.md; pilot-gate.mdIn place
Are releases signed?Yes. Ed25519 signatures over the exact manifest bytes, verified offline against pinned keys. Level: Unit-tested; one signed release was installed into the owner's own account on 2026-11-04.Source: release-signing.md; maturity.md, Signed releases and Installer rowsBuilt, not proven in a district
Is test data real?No. Tests use only synthetic fixtures with .example domains, and a test enforces it.Source: threat-model.md T14In place
How is untrusted code isolated?Gadgets and agents start with no access and run in a sandbox that reaches the internet only through the gatekeepers a person granted. Imported content is treated as data and cannot change policy or tools.Source: README.md (repository root); threat-model.md boundaries 5-7, T7In place (Cloudflare OS sandbox)Built, not proven in a district (EducateOS policy)

Open items

These answers are marked not done or unknown because no EducateOS document settles them yet. We'll update this page as each is settled.

  • A dedicated security contact and a vulnerability disclosure policy.
  • A written incident response plan and a breach notification commitment for the installation (the DPA's 72 hours covers only data Gmacko Ventures LLC holds).
  • Cyber liability insurance, if any.
  • Background checks for anyone who would do Support Access.
  • Whether to pin the district Durable Object to Cloudflare's us jurisdiction, and a backup and restore procedure with committed RTO and RPO.
  • Counsel's review of the DPA (SCHO-229).
