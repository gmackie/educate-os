MCP

Bring any MCP server to your classroom agents.

The Model Context Protocol (MCP) is how AI tools talk to outside services. In EducateOS, an MCP server is one more gatekeeper: agents can use its tools, reads are recorded, and anything that changes data waits for a person.

Agents call MCP servers

Paste an endpoint. Pick the tools. Approve the writes.

Available in Cloudflare OS
  • Paste a server's address. The connector runs the server's own sign-in, and each of its tools becomes something the agent can call. The server needs no EducateOS-specific work.
  • A grant lists the tools it allows, so a class agent can search a catalog without also being able to delete from it.
  • Tools the server marks read-only return straight away and are recorded. Every other call, including tools with no marking at all, queues for approval.
  • Nothing a self-added server claims about itself can make a write skip the approval prompt.

The MCP client is part of Cloudflare OS and covered by unit tests. It uses the official MCP TypeScript client.

For administrators

One portal, chosen by the district, so no teacher types an endpoint.

Available in Cloudflare OS
  • The administrator configures one portal address. Everyone then reaches the MCP servers the district approved, and nothing else.
  • The intended portal is a Cloudflare MCP server portal. Cloudflare Access decides who may connect, and Cloudflare Gateway logs and inspects the traffic.
  • Every grant names a single server behind the portal. "Everything the portal offers" isn't an option.
  • Only a portal can ever auto-apply a write, and only if the administrator turns on trust for the servers behind it and a person enables a rule for that kind of action. Trust is off by default.

Your district as an MCP server

Let the AI tools staff already use reach school data, under the district's rules.

Planned

The design gives each district its own MCP server, so an approved outside AI client could call the district's school tools. It is designed and has no code yet.

  • The same operation, handler and policy decision as the district's own app, whether it's called from the web or over MCP.
  • Standard OAuth sign-in. A token meant for another service is refused, and revoking access takes effect at once.
  • An admin page to preview what an approved agent could reach before it's switched on.
