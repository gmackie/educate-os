Integrations · OneRoster 1.2 and ClassLink

OneRoster 1.2 rosters, previewed before anything changes.

EducateOS reads OneRoster 1.2 from a CSV export or a REST endpoint, which covers ClassLink and many student information systems. Every import is previewed, conflicting identities are quarantined, and nothing is ever deleted.

What happens when something goes wrong

  • A provider that changes its total count or repeats an ID mid-read fails the whole read, and nothing is applied.
  • A second import running at the same time is refused, so two syncs can't interleave.
  • An expired token is refreshed once. Secrets never appear in error messages.
  • A quarantined person's enrollments are neither written nor deactivated until an administrator resolves them.
How we validate. Every status on this page comes from the project's maturity record. Unit-tested features run against fakes that behave like the real service: the synthetic Northfield district's CSV and REST fixtures. A feature moves to "Validating against live sandbox" when a run against the vendor's own sandbox is under way, and to "Supported" only after it passes there. More on our testing →
