Integrations · Clever

Clever sign-in now, Clever rosters next.

Students and staff can sign in with Clever through Cloudflare Access, which EducateOS already uses for sign-in. We're validating that against Clever's sandbox. Roster sync from Clever is planned.

Sync directionInbound only: identities at sign-in, and rosters once sync is built.

Clever features
FeatureWhat it doesStatus
Clever SSO through Cloudflare AccessClever is set up as an OpenID Connect login method in Cloudflare Access. Access passes Clever's user_type, district_id and user_id claims, along with the person's name. Today EducateOS reads the issuer and subject from the Access sign-in, and matches them to a person through an identity link.Validating against live sandbox
District and school mappingUsing district_id to confirm that a person belongs to this EducateOS district, and user_type to check their role against the roster. Each person still matches by (district, issuer, subject), never by email.Planned
Roster sync from the Data API v3A full sync of schools, sections, people and enrollments with a district token (SCHO-203), through the same preview, quarantine and all-or-nothing apply as OneRoster.Planned
Events-based deltasIncremental changes from Clever's events between full syncs. A removal deactivates a person or enrollment and deletes nothing.Planned

How failures are handled

  • A Clever user nobody has linked gets a clear screen saying they haven't been added, not an account.
  • A sign-in from a Clever district that doesn't match the EducateOS district will be refused once claim mapping lands.
  • Roster sync is planned to inherit OneRoster's protections: preview before apply, quarantine of conflicting identities, and deactivation instead of deletion.
How we validate. Every status on this page comes from the project's maturity record. Unit-tested features run against fakes that behave like the real service: the Access sign-in tests. A feature moves to "Validating against live sandbox" when a run against the vendor's own sandbox is under way, and to "Supported" only after it passes there. More on our testing →
