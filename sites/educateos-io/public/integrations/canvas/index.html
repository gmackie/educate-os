Integrations · Canvas

Canvas, through an LTI 1.3 developer key.

A Canvas administrator adds EducateOS as an LTI 1.3 developer key. Teachers can then launch EducateOS activities from course navigation or pick them as assignments, and teacher-approved scores flow back to the Canvas gradebook. Everything below uses the LTI 1.3 tool.

What happens when something goes wrong

  • A launch from a course nobody mapped is refused, with no data read.
  • A person nobody linked sees their Canvas issuer and user ID to give an administrator. No account is created.
  • A score whose maximum or version doesn't match the teacher's approval is refused rather than rescaled.
  • A score already posted isn't posted twice. A failed post is released so it can be retried.
  • A key rotation in Canvas is picked up on the next unknown key ID.
How we validate. Every status on this page comes from the project's maturity record. Unit-tested features run against fakes that behave like the real service: Canvas placement fixtures, the LTI tests. A feature moves to "Validating against live sandbox" when a run against the vendor's own sandbox is under way, and to "Supported" only after it passes there. More on our testing →

EducateOS claims no 1EdTech certification. "LTI 1.3" and "LTI Advantage services (Deep Linking, AGS, NRPS)" describe the specifications the code is written to, not certified conformance.
