Marketplace

Curriculum packs, signed by their publishers.

A curriculum pack is a set of ready-to-edit activities. Your district checks each one's signatures against keys it already holds before it installs it, and never asks educateos.io anything. Every listing here is free.

In development Districts install packs through their own API today; a console page comes next. Signed blueprints and capability packs are planned.

How installing works

Checked in your district, offline.

  • A district administrator downloads a signed listing and installs it into the district. The district Worker never fetches it from educateos.io.
  • The district checks three signatures before installing: an EducateOS release key it pins vouches for the publisher's key, the publisher's key signs the listing, and the listing names the exact content by its SHA-256 digest. If any check fails, the district installs nothing.
  • Teachers then add a pack's activities to their own classes as drafts and edit them before publishing. A pack names nothing from the publisher's own district: no resources, rubrics or learning goals.
  • Once installed, a pack keeps working even if its publisher's credential expires or educateos.io is unreachable. Nothing at runtime checks a licence or a subscription.
For publishers and self-hosters

An open format.

A listing is one JSON file in the educateos.marketplace.listing/v1 format: the publisher's credential, the signed listing and the pack. The format and the verifier are open source, in @educateos/marketplace. A district that runs its own release keys can admit its own publishers with them.

Paid listings are not offered. If they are added, each purchase will be delivered as its own signed file that the district verifies the same way.
